ทำไม Node เร็วกับงานเว็บ? มันมี thread หลักตัวเดียว (single-thread event loop) พอ request เข้ามา มันส่งงานช้า ๆ อย่างอ่านไฟล์หรือ query DB ออกไปทำ แล้วหันไปรับ request ถัดไปทันทีโดยไม่รอ (non-blocking) งานไหนเสร็จก็ค่อยตอบกลับ เลยเหมาะกับแอปที่ I/O เยอะ, real-time, JSON API แต่ถ้าเป็นงานคำนวณหนัก ๆ thread ตัวเดียวจะค้าง Node จึงไม่เหมาะ

Web Services: HTTP, JSON, REST และการเรียก API ด้วย JS

บทนี้ทฤษฎีเยอะที่สุด แต่เราจะดูผ่านของจริงที่วิ่งอยู่ในเครือข่าย คือหน้าตา HTTP message, JSON, storage ใน browser และโค้ดเรียก API

1ก่อนมีเว็บ: tier ต่าง ๆ

ระบบสารสนเทศมี 3 layer คือ presentation (UI), application logic และ resource management (DB) จะวางไว้กี่เครื่องเรียกเป็น tier: 1-tier รวมทุกอย่างในเครื่องเดียวแบบ mainframe ขยายยาก, 2-tier คือ client-server (UI อยู่ client, ข้อมูลอยู่ server), 3-tier แยกทั้งสาม layer เป็นอิสระ (front-end, middleware, back-end) และ N-tier หรือ distributed application ที่เพิ่ม application server หลายตัวเพื่อกระจาย business logic

2HTTP message หน้าตาเป็นแบบนี้

request · response

header อื่นที่ควรรู้: User-Agent (browser/OS ที่ส่งมา), Authorization (token สำหรับเข้า resource ที่ป้องกันไว้) สถานะหลักคือ 200 OK, 404 Not Found, 500 Internal Server Error HTTP ออกแบบให้ง่าย คนอ่านออก ขยายได้ และเป็น stateless แต่ยังมี session ได้ (ผ่าน cookie) ส่วน MIME type คือตัวบอกชนิดของเอกสาร

3XML กับ JSON

HTML บอกได้แค่ว่าจะแสดงผลยังไง XML จึงเกิดมาเพื่ออธิบายตัวข้อมูล tag ตั้งเองได้ โปรแกรมอ่านได้ ไม่ได้ทำมาให้ browser แสดง และมี XML Schema กำหนดชนิดข้อมูล

XML · JSON

5Web service และ REST

W3C นิยาม web service ว่าเป็นระบบที่ให้เครื่องคุยกับเครื่อง (machine-to-machine) ผ่าน network ข้อมูลมักเป็น XML (SOAP, POX) หรือ JSON มาตรฐานที่เกี่ยวข้องคือ SOAP, WSDL, HTTP และ REST ทุก web service เป็น API แต่ API บางตัวไม่ใช่ web service เพราะ web service ต้องใช้ network เสมอ

REST เป็น architecture style ไม่ใช่ protocol และไม่ใช่มาตรฐาน มันหยิบ HTTP, URL, JSON/XML และ MIME type มาใช้ แล้วกำหนดกติกา 6 ข้อ

Constraintแปลว่า
Client/Serverแยก UI กับ data ให้พัฒนาแยกกันได้
Statelessserver ไม่จำอะไร ทุก request ต้องมีข้อมูลครบ
Cacheableresponse ต้องบอกว่า cache ได้ไหม (เสี่ยงได้ข้อมูลเก่า)
Uniform Interfaceresource หนึ่งมี URI เดียว ใช้ GET/POST/PUT/DELETE แบบเดียวกันหมด
Layered Systemclient ไม่รู้ว่าคุยกับ server จริงหรือตัวกลาง
Code-On-Demandส่งโค้ดไปรันที่ client ได้ เป็นข้อเดียวที่ optional

Uniform interface ยังแตกเป็น 4 หลัก: ระบุ resource ด้วย URI (ใช้คำนาม ไม่ใช้กริยา), resource representation (HTML, XML, JSON ตามที่ client ขอผ่าน Accept), self-descriptive messages (มี metadata พอให้รู้ว่าต้องจัดการยังไง) และ HATEOAS (ใน response มี link ให้เดินต่อไปยัง resource อื่น)

จุดที่ข้อสอบชอบหลอก

  • PUT idempotent ส่วน POST ไม่
  • Accept คือสิ่งที่ client อยากได้ Content-Type คือชนิดของ body ที่ส่ง
  • localStorage ไม่ถูกส่งไป server ส่วน cookie ถูกส่งทุก request

5ล็อก API ด้วย JWT

flow คือ ผู้ใช้ login → server สร้าง token ส่งกลับ → client เก็บไว้ (localStorage, sessionStorage หรือ cookie) → ทุกครั้งที่เรียก API แนบ header Authorization: Bearer <token> → server ตรวจ token ผ่านก็ให้ข้อมูล ไม่ผ่านตอบ 401

JWT หน้าตาเป็น xxxxx.yyyyy.zzzzz คือ header (ชนิด token กับ algorithm เช่น HS256), payload (claims ซึ่งมี registered claims อย่าง iss, exp, sub, aud, iat, public claims และ private claims ที่ตกลงกันเอง) และ signature ที่สร้างจาก header กับ payload ที่ encode แล้ว + secret + algorithm

server (npm install --save jsonwebtoken)
client: login แล้วแนบ token

6เรียก API จากฝั่ง Node ด้วย Axios

Axios ใช้ได้ทั้ง browser และ Node แปลง JSON ให้อัตโนมัติ ตั้ง timeout และยกเลิก request ได้ มี CSRF protection และดู upload progress ได้ ตัวอื่นที่ทำงานคล้ายกันคือ http, request, needle, superagent, got, node-fetch

จุดที่ข้อสอบชอบหลอก

  • ต่างแค่ port ก็เป็น cross-origin แล้ว
  • payload ของ JWT แค่ encode ใครก็ถอดอ่านได้ ตัวกันปลอมคือ signature
  • middleware ที่ไม่เรียก next() จะทำให้ request ไปไม่ถึง handler

Lab14

InfoForm สองแบบด้วย React

โจทย์: ทำ component InfoForm ที่แสดงฟอร์มได้สองแบบตาม props.type แบบ normal มีชื่อ นามสกุล อายุ แบบ special เพิ่มสัญชาติกับความพิการ กด Submit แล้ว alert ข้อมูล เนื้อหาอยู่ในบท L14

ไฟล์ที่ส่ง: reactlab/src/index.js (โปรเจกต์สร้างด้วย create-react-app)

1import

index.js

react คือตัว React เอง ส่วน react-dom/client มี createRoot ไว้เอา component ไปวางลงหน้าเว็บ โค้ดทั้งหมดอยู่ใน index.js ไฟล์เดียว App.js ที่มากับโปรเจกต์ไม่ได้ใช้

2ตอนกด Submit

index.js

InfoForm เป็น function component รับ props จากคนที่เรียกใช้ ข้างในประกาศ handleSubmit เป็น arrow function

event.preventDefault() ห้ามไม่ให้ฟอร์มส่งแล้วรีโหลดหน้าเอง (ใน React ใช้ return false ไม่ได้) จากนั้น new FormData(event.target) อ่านค่าทุกช่องของฟอร์มที่เพิ่ง submit แล้ว data.get("ชื่อ") ดึงค่าตาม attribute name ของ input

สุดท้ายเช็ค props.type เพื่อเลือกข้อความ \n ใน template literal คือขึ้นบรรทัดใหม่ใน alert

3วาดฟอร์ม และแสดงช่องพิเศษตามเงื่อนไข

index.js

onSubmit={handleSubmit} ผูก event แบบ React คือ camelCase และส่งฟังก์ชันเข้าไป ไม่ได้เป็น string

บรรทัด {props.type === "special" && ( ... )} คือเทคนิคแสดงตามเงื่อนไข ถ้าเงื่อนไขซ้ายเป็น false ทั้งก้อนจะไม่ถูกวาด ถ้า true จะได้ JSX ทางขวา ส่วน <> ... </> คือ Fragment ใช้ห่อหลาย element โดยไม่เพิ่ม div เกินเข้าไปในหน้า (JSX ต้องคืนก้อนเดียว)

ฟอร์มนี้เป็นแบบ uncontrolled คือปล่อยให้ input เก็บค่าเอง แล้วค่อยอ่านตอน submit ต่างจาก controlled ในสไลด์ที่ผูกค่ากับ state ทุกครั้งที่พิมพ์

4เอาไปแสดงบนหน้า

index.js

หา <div id="root"> ใน public/index.html สร้าง root แล้ว render InfoForm พร้อมส่ง prop type="special" อยากดูแบบ normal ก็เปลี่ยนเป็น type="normal" ส่วน README ของแลปใช้ ReactDOM.render(...) ซึ่งเป็นวิธีเก่า React 18 ขึ้นไปใช้ createRoot แบบในโค้ดนี้

จุดที่ควรแก้

โจทย์เขียนว่าให้พัฒนา "คลาส InfoForm" แต่โค้ดเป็น function component ทำงานได้เหมือนกัน แต่ถ้าข้อสอบให้เขียนแบบ class ควรเขียนได้ด้วย ลองเทียบกับเวอร์ชัน class แบบ controlled ข้างล่าง

เวอร์ชัน class (controlled)

อีกเรื่อง: ฟอร์ม special มีช่อง Disability แต่ alert ไม่ได้แสดงค่านี้ ถ้าตัวอย่างผลลัพธ์ในโจทย์มีแสดงด้วย ต้องเพิ่ม data.get("disability") ลงในข้อความ
